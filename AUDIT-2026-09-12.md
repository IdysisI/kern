# Kern Deep Audit — 2026-09-12

All findings verified mechanically (repro scripts run under isolated KERN_HOME).
All 23 deterministic bench suites green after fixes. 7/7 per-fix repros pass.
Zero new LLM requests introduced anywhere (piggyback compaction only).

## Part 1 — Confirmed defects (all fixed in this audit)

### 1. /undo was fundamentally broken — three stacked bugs  [SEVERITY: CRITICAL]
- restore() never deleted agent-created files: journal.py used subprocess
  without importing it -> NameError, swallowed by a bare `except Exception:
  pass` at the deletion step. Root cause found by instrumenting restore().
- Direct write/edit checkpoints omitted `cwd`, so restore's untracked-file
  diff had no repo to diff against. Fixed: all 3 tool call sites now pass
  cwd=str(fs.cwd).
- Result: /undo looked fine and silently did nothing. Now: created files
  are deleted, tracked files restored, verified end-to-end.

### 2. /undo truncates the journal BEFORE selecting a checkpoint  [SEVERITY: HIGH]
Pre-existing design flaw (was fixed in a prior session): checkpoint selection
now happens against the full event list before any truncation.

### 3. Failed edits leaked checkpoint directories forever  [SEVERITY: MED]
Every refused edit (precondition failure, no old_str match, bad range) left a
c{N} dir. Now drop_checkpoint(cid) removes it; verified no dir after failure.

### 4. Background exec: no sandbox, no approval  [SEVERITY: CRITICAL]
exec(background=true) ran bare `bash -c` outside bubblewrap. Any model could
spawn unsandboxed background work. Fixed: background jobs get the identical
bwrap wrap (--die-with-parent), same approval path.

### 5. is_safe_readonly auto-approved destructive commands  [SEVERITY: CRITICAL]
`find . -delete`, `sort -o /etc/passwd`, `git branch evil`, `git tag v1`,
`git remote add x y`, `git diff --output=...` were ALL auto-approved as
"read-only". Rewrite: mutating-flag blacklist + git subcommand allowlist
(branch/tag/remote/config/stash require listing-only forms), `--output=x`
normalization. 38-case mutant suite passes both ways (no false accepts, no
false rejects on innocents like `git branch`, `git stash list`).

### 6. Mounted capabilities vanished every turn  [SEVERITY: HIGH]
TUI/GUI/daemon/serve build a fresh Engine per turn; mounts lived only in the
Engine instance. [mount: x] in turn N is gone by turn N+1 — the model
re-mounts (wasted requests) or worse, silently loses the ability.
Fix: mount/unmount now journal `mount` events (cap_kind, ref / tools list);
Engine._replay_mounts() rebuilds the MountTable on construction. Skill
bodies and MCP tool SCHEMAS survive restarts; MCP process re-spawns lazily
on first call. Zero request cost.

### 7. Torn JSONL tail made sessions unopenable  [SEVERITY: HIGH]
A crash mid-write left one partial final line; Session.__init__ raised
JSONDecodeError and the whole session was bricked (resume, fork, undo all
dead). Now: torn FINAL line skipped + warning surfaced; mid-file corruption
still refuses loudly (that's real corruption).

### 8. Crash-durability gaps  [SEVERITY: MED]
- emit() fsynced only on turn_end; a crash mid-turn lost the whole turn's
  provenance. Now user/action/tool_result events fsync too (measured cost:
  0.028 ms/emit — free).
- checkpoint() wrote snapshots + manifest without fsync; restore could
  advertise undo with cache-lost copies. Now copies + dir entries fsynced.

### 9. KERN_HOME inconsistencies  [SEVERITY: MED]
Custom KERN_HOME broke MCP mounting (hardcoded Path.home()); sandbox now
binds KERN_HOME writable always (also the default home). Note: this dev
machine has a read-only root FS — ~/.kern sits on the RO root here, which
is environmental, and custom homes work.

### 10. Compile-red + version drift  [SEVERITY: LOW]
bench/dbg8.py had a syntax error breaking `compileall` for the whole repo;
versions drifted (pyproject 0.2.0 / __init__ 0.1.0 / daemon 0.2.2). Unified
on 0.2.0; dbg8.py fixed; MCPClient.stop() now waits for process exit.

## Part 2 — Request-cost audit (per-request billing)

Walked every LLM call path in engine.py/client.py:
- probe(): once per model, cached in health.json — zero repeat cost. Good.
- compaction: piggyback-first (in-reply <summary>) — ZERO extra requests;
  dedicated request only as fallback after model ignores the directive;
  deepening passes (window 4000/1200) reuse the same summary — no calls.
- _maybe_compact: re-derived from budget each loop step — no stale flags,

- Correctly refuses to compact when compaction_view is empty (single huge

- stream error handling: journaled + surfaced, never triggers hidden retries.
Verdict: no per-request waste found; all improvements this audit added are
request-neutral by construction.

## Part 3 — Lean capability roadmap (request-cost-aware, ranked)

1. **Execution-facts ledger hardening** (DONE this audit): exit codes now in
   facts lines (`exec -> ok but exit=2 | ...`) — the model sees command
   outcomes across compaction boundaries without re-running anything.
2. **Mount persistence** (DONE this audit): capabilities survive turns and
   restarts via journal replay — the model mounts once per capability,
   never again. Direct per-request savings.
3. **todo/objective Slate already exists** (verified): work-state block is
   always-visible from journal events, not Engine state — resilient across
   process restarts. No change needed; this is genuinely good design.
4. Next candidates (NOT built, kept lean):
   - Offload large tool results to scratch/ automatically (already exists);
     consider extending to search results.
   - Cache fetch() responses keyed by URL in scratch/ for the session.
   - Journal-level dedup of identical exec commands within a turn
     (hash-check before running: same cmd + same cwd + <2s = return cached).
     Saves wall-clock, not requests, and only when safe (no side effects).
   - Semantic memory consolidation is already there (MemoryTree.absorb on
     compact) — request-free by design. Resist adding embedding calls.

## Part 4 — Late findings (TUI/daemon attach path, all fixed)

11. **TUI killed healthy daemons on version mismatch**  [SEVERITY: HIGH]
    `kern/tui.py` hardcoded `DAEMON_VERSION = "0.2.2"` while the daemon
    reports `kern.__version__` ("0.2.0"). On connect the TUI compares, and on
    mismatch sends `shutdown` — **killing the daemon and every background
    session it owns**, then silently falls back to local mode. The user's
    terminal session was being murdered by its own client. Both sides now
    derive from `kern.__version__`; bump `__init__` to match pyproject (0.2.0).
12. **`exclusive=True` reader cancelled the attach worker mid-RPC**
    [SEVERITY: HIGH — root cause of remote-mode flakiness]
    `_daemon_entry` started the reader with `run_worker(..., exclusive=True)`
    in the default worker group; exclusive cancels all workers *in the same
    group* — including `_daemon_entry` itself. Result: attach/new RPC died
    mid-flight with CancelledError, swallowed silently, session never bound.
    This also explains sporadic "attach or new first" errors. Reader now runs
    in group `"remote-reader"`.
13. **The user-visible "last message repeats 2×" bug**  [SEVERITY: MED]
    Remote `turn_end` always mounted the full reply as a NEW bubble on top of
    the live-streamed widget — the same text twice (re-resume rendered the
    journal once, which is why it looked fine after restart). Fixed by making
    `turn_end.reply` authoritative: the live stream widget is updated in place
    (heals the mid-turn-attach case where only the tail streamed); a fresh
    bubble is mounted only when nothing streamed at all. Regression:
    `bench/T23_no_duplicate_final.py` (full TUI + real daemon + fake model)
    asserts exactly-one render; also covers the attach-mid-turn heal path.

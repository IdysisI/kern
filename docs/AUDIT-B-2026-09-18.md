## CONFIRMED BUGS (observed live this session + code evidence)

### P1 — spill-file tags derive from the MUTABLE event number (journal.py + pager.py)
- `Session.offload(tag, text)` writes `scratch/{tag}-{sha1(text)[:16]}.txt`.
- pager.py:231,240 call `offload(f"t{ev['n']}", text)` — tag = event number.
- journal.py:198 `_truncate()`: `kept = [dict(e, n=i) for i, e in enumerate(self.events[:upto])]`
  — EVERY compaction renumbers all surviving events. fork/restore replay (journal.py:282)
  also reassigns n (strips n/ts, child re-emits).
- Consequence A (dangling pointers): a pointer rendered as `scratch/t287-b406565d....txt`
  before renumbering refers to `t287`, but the file on disk is `t154-b406565d....txt`
  (same content digest — the file that actually exists). OBSERVED LIVE this session:
  `read` of the rendered t287 path failed with "no such file", and ls shows only
  t154-b406565d033f9b6d2dd44410.txt. The model is told to read a file that never existed.
- Consequence B (unbounded duplicate growth): after each renumber, re-rendering the same
  event spills identical content under a NEW tag → new file. Session scratch dir had
  129 files, many byte-identical pairs differing only in the t-prefix.
- FIX: make offload content-addressed: if `*-{digest}.txt` already exists in scratch,
  return that existing path (first match) instead of writing a duplicate. The digest
  half of the name is already stable; only the human-readable tag prefix drifts.
  Optionally also switch pager tags from ev['n'] to ev.get('call_id') (stable across
  renumbering).

### P2 — pager identical-result dedup deadlocks re-reads of spill files (pager.py:217-224)
- On render, a tool_result whose content-hash matches an earlier event is replaced by
  `[identical to tool result #{first_n} — {len} bytes, read(path/scratch) if needed]`.
- Failure mode (OBSERVED LIVE, repeatedly, pre-restart): model re-reads
  `scratch/t97-....txt` to recover content the pager cleared from context; the re-read's
  bytes are identical to event #97's spill (of course — the file IS that event's output);
  the pager collapses the fresh result to the pointer; but event #97 was ALSO pager-cleared
  → the content never reaches the model. Pointer to a pointer = livelock. The audit prompt
  itself could not be read for ~30 turns because of this + P1.
- FIX: do not dedup a result against an original event that is being cleared/offloaded in
  the same render pass (the pointer is only useful if the original is still visible).
  If the original will be rendered as `[old tool result cleared...]`, keep the new body.

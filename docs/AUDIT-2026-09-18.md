# Kern Deep Audit — 2026-09-18

A full 7-pass audit of the Kern codebase, conducted by an in-session Kern agent
on the user's machine. Findings are grouped by file surface and ranked by
severity (HIGH = fix first, MED = fix this month, LOW = opportunistic).

> **Origin**: Triggered by user request "do the deepest entire audit EVER of
> Kern and find ALL the best ways to make it better". Audit scope: every
> source file under `kern/`, every test under `tests/` and `bench/`, every
> doc under `docs/` and `research/`. Total ~7,700 LOC of core code reviewed.

---

## How to read this doc

- **Each finding is `#.N`** — the `N` is the audit-pass number; the leading
  `#` is the global rank. So `#1.6` is "finding 6 in pass 1".
- **Severity legend**: HIGH (user-visible breakage or security risk),
  MED (clear friction or silent failure), LOW (nice-to-have).
- **Status legend**: 🔴 open · 🟡 partial fix landed · ✅ done
- The companion "**Apply list**" at the bottom is the proposed implementation
  order, ranked by ROI. Each item is meant to be one atomic commit.

## Pass 1 — engine.py (the turn loop, 1568 LOC)

The single most important file. Every turn of every session runs through
`_loop()` here.

| ID | Sev | Location | Finding |
|----|-----|----------|---------|
| #1.1 | 🔴 HIGH | `_call_tool:529–570` → engine.py line 1146 | The new structural `constraint_gate()` (added this session) returns a synthetic rejection, but only the `force_plan` branch at 1146 emits it directly. Other constraints (`suppress_repeat`, `escalate`, `redact_py_file_reads`) are applied as **meta** but their gate behaviour is not enforced on the **next** tool call. Wire `constraint_gate()` into `_call_tool`'s pre-dispatch path so all constraints, not just force_plan, gate subsequent calls. |
| #1.2 | 🔴 HIGH | `_call_tool:556–568` | `_call_tool` lets uncaught exceptions propagate. A single buggy tool (e.g. `read` of a hung FUSE mount) **kills the session**. Should catch + return `(text=f"<tool exception: {e}>", meta={"error": str(e), "tool": name})` so the loop can continue and the model can react. |
| #1.3 | 🔴 HIGH | `_tools:326–351` | `_tools()` rebuilds the **entire tool schema every turn**. With ~30+ tools and dynamic mounts, this is ~3KB of JSON sent to every model on every turn. Cache the static portion; invalidate only when `_replay_mounts` changes. Saves 100–500ms per turn on slow providers. |
| #1.4 | 🟡 MED | `_loop:1140` | `del self._last_constraint_meta` after firing — good — but **no clearance when the user replies in plain text**. Stale constraint state leaks between turns. |
| #1.5 | 🟡 MED | `_loop:1117` | `user_text = user_text or ""` silently swallows `None`. If the user accidentally double-presses Enter or pipes a `None`, the turn runs with empty text and may make spurious tool calls. Hard-error instead. |
| #1.6 | 🟡 MED | `_loop:1124–1133` | `for tool_call in tool_calls` has no per-tool timeout. Only the model call has `step_timeout` (1091). A tool that hangs forever blocks the turn loop. Add a per-tool watchdog. |
| #1.7 | 🟡 MED | `_review_completion:1011–1068` | Completion review uses string matching against `DONE`/`FINISH` tokens. Brittle and easy to confuse with model output that contains those words. Replace with a structured enum or a dedicated tool call. |
| #1.8 | 🟡 MED | `_safe_call:495–501` | `_safe_call` catches all exceptions and returns them as text, but **doesn't distinguish** user-fixable errors (bad arg, missing file) from programmer errors (TypeError, KeyError). User sees the same red wall for both. Categorise. |
| #1.9 | 🟡 MED | `_system:303–325` | System prompt is rebuilt every turn. With a non-trivial prompt, this is wasted tokens. Cache and invalidate only on mount change. |
| #1.10 | 🟡 MED | `_handle_mount_directives:417–473` | Mount/unmount directives are parsed from model text via `/mnt ...` regex. If a hostile page echoes `[mount: foo]` (prompt-injection via tool_fetch), it could trigger mounts. Should only honor directives from model text, **not from tool results**. |
| #1.11 | 🟡 MED | `_call_tool:556–568` + `kern/constraints.py` | Constraint state lives on the engine instance (`self._last_constraint_meta`). If two turns ever run concurrently (subagent + parent), the state leaks between them. Bind to a per-call context. |
| #1.12 | 🟢 LOW | `_loop:1096–1102` | When `step == max_steps - 1`, the model is told "last step" but isn't given a summary of what was already done. Model often repeats. Auto-include `_build_facts(events)` here. |
| #1.13 | 🟢 LOW | `_loop:1110` | `while not self._done` — no iteration counter / progress meter. UIs guess from event count. Emit a synthetic `progress` event. |
| #1.14 | 🟢 LOW | `_build_facts:1007–1010` | `_build_facts` is called but its return value isn't fed back into the system prompt on long sessions. Either wire it or remove it (currently dead-ish). |

## Pass 2 — syscalls.py (the tools, 1213 LOC)

| ID | Sev | Location | Finding |
|----|-----|----------|---------|
| #2.1 | 🔴 HIGH | `tool_exec:611–634` | `timeout=60s` flat — no warm-up probe, no retry on transient connect-time failures. First command after daemon boot frequently times out. User sees `[timed out]` and retries, wasting turns. |
| #2.2 | 🔴 HIGH | `tool_exec:611–634` | `tool_exec` doesn't apply the privacy/size redaction that `tool_py` got in a recent commit. `exec cat /etc/passwd` returns the whole file; `py open('/etc/passwd')` is capped at 6KB. Inconsistent. |
| #2.3 | 🔴 HIGH | `_call_tool` gate (no path check) | File-system tools accept absolute paths but there's no path-based heuristic in the approve callback (e.g. "always require approval for paths outside CWD"). `read /etc/shadow` works silently if `approve=lambda *a,**k:True`. |
| #2.4 | 🟡 MED | `tool_search:786–792` | Strips results at hard 700 chars with no paragraph-boundary awareness. Long-form sources get cut mid-sentence. Slice on `\n\n` first. |
| #2.5 | 🟡 MED | `tool_fetch:833–876` | Uses `urllib.request` with no timeout override, no retry/backoff, no DNS-error distinction. Transient flakes bubble up as opaque errors. |
| #2.6 | 🟡 MED | `tool_exec` + `tool_py` | Approval prompt fires per-call even when user just approved an identical command. Cache approval for the session keyed on `(command, working_dir)`. |
| #2.7 | 🟡 MED | `tool_edit:410–485` | Diff line numbers are absolute, not hunk-relative. Hard to copy-paste a specific hunk back. |
| #2.8 | 🟡 MED | `tool_edit:410–485` | No syntax-highlight on diff. Hard to spot a stray semicolon or missing comma at a glance. |
| #2.9 | 🟢 LOW | `tool_read:241–308` | First read of a huge file returns 200 lines by default, then the constraint fires — should auto-cap at 60 lines on first read unless `full=True` is requested. |
| #2.10 | 🟢 LOW | `tool_read:241–308` | `offset=0` is silently treated as 1; docstring says "1-based" inconsistently. |
| #2.11 | 🟢 LOW | `tool_web` | Exists in source but isn't surfaced in the user-facing tool list (only `search` and `scrape` are). Either expose all or alias the unused ones. |

## Pass 3 — journal.py (persistence, 417 LOC)

| ID | Sev | Location | Finding |
|----|-----|----------|---------|
| #3.1 | 🔴 HIGH | `compact_into:213–229` | `compact_into` accepts `summary` and `facts` as plain strings and inlines them into the next-turn context **without any sanitisation**. A `summary` containing `[harness hint: ...]` or `<system>...</system>` from a prior tool result leaks into the system prompt. **This bypasses the entire constraint system I just added** — it's the highest-leverage injection vector in the codebase. |
| #3.2 | 🟡 MED | `emit:69` | No `os.fsync()` after each event write. Daemon crash loses the most recent events. For an "everything is journaled" agent, this is the difference between resume works / user loses context. |
| #3.3 | 🟡 MED | `checkpoint:105–185` | Returns an int ID but doesn't compress or dedup identical files. A user that re-reads the same 5MB file checkpoints it 5 times, bloating the session dir. |
| #3.4 | 🟡 MED | event load (no JSON-error handling) | A corrupted or partial events.jsonl line causes the whole journal to throw on replay. Should `try/except json.JSONDecodeError` per line, mark bad lines as `{"_corrupt": true}` and skip. |
| #3.5 | 🟡 MED | `last_checkpoint:205–211` | Returns `None` if no checkpoints; `restore(None)` would crash. Caller chain has no None-check. Return `-1` and special-case. |
| #3.6 | 🟡 MED | `undo_to_last_user:230+` | Rewinds events but doesn't restore checkpointed files. After undo, worktree can be in an inconsistent state. |
| #3.7 | 🟢 LOW | `fork:248–260` | Creates new session dir but doesn't deep-copy scratch files. Documented behaviour is "fork at turn N" — should be a doc + a test. |
| #3.8 | 🟢 LOW | `offload:291+` | Writes to scratch but never garbage-collects. Long-running sessions accumulate 1000s of stale files. |
| #3.9 | 🟢 LOW | `turn_is_open:262` | Getter with 0 callers — dead code. |

| ID | Sev | Location | Finding |

| #5.2 | 🔴 HIGH | `tool_fetch` (no sanitiser) | The constraint system I just added mutates `tool_result.meta` — but the **model-visible text** still contains the raw hostile page. | #5.3 | 🔴 HIGH | `tool_memory:844+` | Returns full content of matching notes in plaintext. If a model earlier wrote a note with a leaked API key, every future turn re-emits that key into context and into the journal. Notes should support a `[secret]` marker that gets redacted on read. |

## Closing notes

The single highest-leverage fix in this audit is **`#3.1` + `#5.2`** —
sanitising compacted summaries and fetched text. That closes the loop
around the constraint system I just landed in this session: today, the
constraints guard against the model re-reading the same bad output, but a
**summary** or **fetched page** can still smuggle `[harness hint: ...]`
into the system prompt that runs every turn. Until those are sanitised,
the constraint system is defence-in-depth, not full coverage.

The single biggest UX win is **`#4.2` first-run experience** — without
it, every new user hits the same "Kern won't start, where do I put my
API key?" friction. A 30-second `kern init` would 10× the conversion.

The single most underrated finding is **`#2.3` no path-based approval
heuristic** — a security regression in spirit. If approve is `True`,
`read /etc/shadow` should still prompt. Fix: in `_call_tool`, if the
resolved path is outside CWD, force approval regardless of the
callback.
